# ربات هوش مصنوعی بله

نسخهٔ آماده‌سازی‌شدهٔ پروژهٔ موجود برای انتشار در GitHub و اجرا به‌صورت **Background Worker روی Render**. منوها، چندزبانگی، حافظه، اخبار، آب‌وهوا و قابلیت‌های رسانه‌ای نسخهٔ اصلی تا حد امکان حفظ شده‌اند.

## امکانات

- ربات بله با polling؛ در هر اجرا فقط یک حلقهٔ polling فعال می‌شود.
- منو و رابط چندزبانه، حافظهٔ مکالمه با ماندگاری ۲۴ ساعت، اخبار فارسی و آب‌وهوا.
- سه پروفایل هوش مصنوعی با سهمیه‌های مستقل برای هر کاربر.
- مدیر با شناسهٔ عددی `ADMIN_ID` از سهمیهٔ مدل‌ها معاف است.
- مدیریت timeout، خطاهای HTTP، پاسخ نامعتبر و خطای اتصال سرویس‌های هوش مصنوعی.
- تنظیم کلیدها فقط از Environment Variables؛ کلید واقعی نباید در سورس یا مخزن قرار بگیرد.

## ساختار فایل‌ها

- `bot.py` — منطق ربات، رابط کاربری، اتصال به بله، مدل‌ها و SQLite.
- `.env.example` — نمونهٔ تنظیمات بدون کلید واقعی.
- `.gitignore` — جلوگیری از ثبت فایل‌های محرمانه و فایل‌های موقت.
- `requirements.txt` — وابستگی‌های Python.
- `render.yaml` — تعریف Worker و دیسک پایدار Render.
- `tests/test_core.py` — تست‌های محلی منطق سهمیه و OWEN.

## پروفایل‌ها و محدودیت‌ها

| پروفایل نمایشی | سرویس واقعی | سقف | بازه |
|---|---|---:|---:|
| ChatGPT | GapGPT | ۴ پیام | ۶ ساعت |
| OWEN | غیرفعال؛ هیچ API فراخوانی نمی‌شود | ۲ پیام | ۴ ساعت |
| Gemini | OpenRouter | ۳ پیام | ۶ ساعت |

سهمیه‌ها بر اساس شناسهٔ کاربر و شناسهٔ پروفایل جداگانه در SQLite ذخیره می‌شوند. پیام‌های منو و `/start` سهمیهٔ مدل را مصرف نمی‌کنند. درخواست موفق مدل سهمیه را مصرف می‌کند؛ خطای API سهمیه را مصرف نمی‌کند. مدیر فقط وقتی شناسهٔ عددی او با `ADMIN_ID` برابر باشد معاف است؛ نام کاربری به‌تنهایی امتیاز مدیر نمی‌دهد.

وقتی OWEN انتخاب شود، پیام کاربر با همین متن پاسخ داده می‌شود و هیچ درخواست هوش مصنوعی به سرویس خارجی فرستاده نمی‌شود:

> این سرویس در حال حاضر غیرفعال است. لطفاً از یکی دیگر از مدل‌های هوش مصنوعی استفاده کنید.

نام «Gemini» فقط عنوان نمایشی پروفایل سوم است؛ درخواست‌ها از endpoint رسمی OpenRouter فرستاده می‌شوند. مدل OpenRouter باید در متغیر `OPENROUTER_MODEL` مشخص شود. اگر مدل در دسترس نباشد، ربات خطا نشان می‌دهد و بی‌اطلاع کاربر به مدل دیگری تغییر نمی‌کند.

## تنظیمات محیطی

از روی `.env.example` یک فایل محلی با نام `.env` بساز، اما **فایل `.env` را در GitHub بارگذاری نکن**. خود برنامه از فایل `.env` نمی‌خواند؛ در محیط محلی مقادیر را در Environment Variables سیستم قرار بده یا ابزار مدیریت محیطی مناسب را به‌صورت جداگانه استفاده کن. در Render متغیرها را از پنل وارد کن.

- `BALE_BOT_TOKEN` — توکن ربات بله؛ ضروری.
- `GAPGPT_API_KEY` — کلید GapGPT؛ برای پروفایل ChatGPT ضروری.
- `OWEN_API_KEY` — عمداً استفاده نمی‌شود و لازم نیست.
- `OPENROUTER_API_KEY` — کلید OpenRouter؛ برای پروفایل Gemini ضروری.
- `ADMIN_ID` — شناسهٔ عددی مدیر؛ پیش‌فرض `955311935`.
- `GAPGPT_BASE_URL` — آدرس پایهٔ API سرویس GapGPT. مقدار پیش‌فرض از نسخهٔ قبلی پروژه حفظ شده (`https://api.gapgpt.app/v1`) اما در این بازبینی نتوانستم آن را با مستندات رسمی جاری GapGPT مستقل تأیید کنم؛ پیش از استقرار با مستندات/پنل سرویس تطبیق بده.
- `GAPGPT_MODEL` — شناسهٔ مدل معتبر و فعال در GapGPT؛ عمداً مقدار پیش‌فرض ساختگی ندارد.
- `OPENROUTER_BASE_URL` — endpoint رسمی `https://openrouter.ai/api/v1`.
- `OPENROUTER_MODEL` — شناسهٔ کامل مدل از فهرست مدل‌های OpenRouter؛ آن را در https://openrouter.ai/models بررسی کن. شناسهٔ نامعتبر یا مدل غیرقابل‌دسترسی باید خطا بدهد.
- `SQLITE_PATH` — مسیر پایگاه داده. در Render روی `/var/data/bot.sqlite3` قرار داده شده تا روی دیسک پایدار ذخیره شود.
- `BOT_NAME` — نام نمایشی ربات.
- `OPENROUTER_SITE_URL` — هدر اختیاری معرفی برنامه به OpenRouter.
- `MAX_INPUT_CHARS` — حداکثر طول ورودی متنی.
- `LOG_LEVEL` — سطح گزارش‌ها.

قابلیت‌های قدیمی تصویر، صدا و ویدئو نیز متغیرهای اختیاری خود را دارند: `IMAGE_API_KEY`, `IMAGE_API_URL`, `IMAGE_MODEL`, `VOICE_API_KEY`, `VOICE_API_URL`, `VOICE_MODEL`, `VOICE_NAME`, `VIDEO_API_KEY`, `VIDEO_CREATE_URL`, `VIDEO_STATUS_URL_TEMPLATE`, `VIDEO_TIMEOUT_SECONDS` و `VIDEO_POLL_SECONDS`. این APIها مستقل از سه پروفایل چت هستند؛ اگر تنظیم نشوند، قابلیت مربوطه پیام خطا می‌دهد.

## انتشار در GitHub

1. یک مخزن جدید بساز.
2. فایل‌های این پروژه را بارگذاری کن؛ `.env.example` باید ثبت شود اما `.env` هرگز نباید ثبت شود.
3. پیش از انتشار، در تب Code و در فایل‌ها مطمئن شو کلید یا توکن واقعی وجود ندارد.
4. اگر قبلاً فایل حاوی کلید را commit کرده‌ای، حذف فایل در commit جدید کافی نیست: کلید را فوراً در سرویس مربوطه revoke/rotate کن و در صورت نیاز تاریخچهٔ Git را با ابزار بازنویسی تاریخچه پاک‌سازی کن. بعد از بازنویسی، همهٔ همکاران باید نسخهٔ جدید مخزن را دوباره دریافت کنند.

## استقرار در Render

این پروژه polling دارد؛ بنابراین در Render به‌صورت **Background Worker** اجرا می‌شود، نه Web Service. فایل `render.yaml` یک Worker و دیسک پایدار یک گیگابایتی تعریف می‌کند. دیسک پایدار معمولاً به پلن پولی Render نیاز دارد؛ پیش از تأیید Blueprint هزینه و نوع پلن را بررسی کن.

1. مخزن GitHub را به Render متصل کن.
2. Blueprint را از `render.yaml` بساز یا یک Background Worker با همان تنظیمات ایجاد کن.
3. Environment Variables را در پنل Render وارد کن: `BALE_BOT_TOKEN`, `GAPGPT_API_KEY`, `GAPGPT_MODEL`, `OPENROUTER_API_KEY`, `OPENROUTER_MODEL`, `ADMIN_ID`.
4. مقدار `GAPGPT_BASE_URL` و مدل GapGPT را با مستندات جاری سرویس تطبیق بده.
5. برای SQLite از دیسک پایدار با mount path برابر `/var/data` و مسیر `/var/data/bot.sqlite3` استفاده کن.
6. Deploy را اجرا کن و لاگ شروع Worker را بررسی کن. اگر Worker دیگری با همین توکن فعال است، آن را متوقف کن تا polling هم‌زمان یا تداخل دریافت update ایجاد نشود.

## اجرای محلی

Python 3.10 یا جدیدتر پیشنهاد می‌شود.

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows:
# .venv\\Scripts\\activate
pip install -r requirements.txt
python bot.py
```

اگر `BALE_BOT_TOKEN` تنظیم نشده باشد، برنامه با پیام قابل‌فهم متوقف می‌شود. برای پاسخ‌گویی پروفایل‌ها باید کلید و شناسهٔ مدل همان سرویس تنظیم شده باشند. تست‌ها بدون توکن بله و بدون تماس زنده با APIها اجرا می‌شوند:

```bash
python -m unittest discover -s tests -v
```

## تعویض کلیدها و بررسی لاگ‌ها

- اگر کلیدی افشا شد، آن را در پنل سرویس ابطال و کلید جدید ایجاد کن؛ سپس فقط Environment Variable را به‌روزرسانی و Worker را redeploy کن.
- در لاگ‌ها توکن‌ها یا هدر `Authorization` را چاپ نکن. این نسخه کلیدها را در log درج نمی‌کند و خطای API را به پیام کنترل‌شده تبدیل می‌کند.
- برای عیب‌یابی، زمان خطا، نوع خطا و کد HTTP را بررسی کن؛ از ارسال screenshot حاوی متغیرهای محرمانه خودداری کن.

## خطاهای رایج

- **توکن تنظیم نشده:** مقدار `BALE_BOT_TOKEN` را در Environment Variables بررسی کن.
- **کلید نامعتبر (401):** کلید همان سرویس را تعویض و مقدار پنل را بررسی کن.
- **مدل یا endpoint پیدا نشد (404):** `GAPGPT_BASE_URL` / `GAPGPT_MODEL` یا `OPENROUTER_MODEL` را بررسی کن.
- **سهمیهٔ API تمام شده (402/429):** اعتبار حساب، رایگان/پولی بودن مدل و محدودیت سرویس را بررسی کن.
- **Timeout یا 5xx:** چند دقیقه بعد دوباره تلاش کن و وضعیت سرویس ارائه‌دهنده را بررسی کن.
- **سهمیه پس از restart پاک شده:** مطمئن شو `SQLITE_PATH` به دیسک پایدار Render اشاره می‌کند؛ فایل‌سیستم معمولی Worker ممکن است پایدار نباشد.
- **هیچ update دریافت نمی‌شود:** بررسی کن Worker دیگری با همان توکن فعال نباشد و توکن درست باشد.

## وضعیت بررسی

تست‌های محلی نحو Python، منطق سهمیه‌ها، جداسازی کاربران/پروفایل‌ها، رفتار OWEN و خطای تنظیم نبودن توکن را بررسی می‌کنند. این بررسی، اتصال زنده به بله یا تأیید عملی کلیدها/مدل‌های حساب شما نیست. endpoint و مدل GapGPT باید قبل از استقرار از مستندات جاری GapGPT تأیید شوند.
